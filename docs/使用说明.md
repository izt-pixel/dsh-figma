# DSH Figma Bridge · 操作说明

面向**使用者**（要在 Figma 里用 DSH 改稿的人）。讲的是「怎么开机、怎么看面板、坏了怎么修」。

- 想搭环境、看原理、读代码 → [`../README.md`](../README.md)
- 想知道为什么这么设计 → [`plan.md`](plan.md)

---

## 1. 这是什么，一分钟版

一句话：**让 DSH 里的模型真的去改你的 Figma 画布**，而不是吐一段代码让你手动拼。

它不是云服务，三段都在你自己电脑/浏览器里：

```
DSH 模型  ──MCP/stdio──>  本地桥  ──HTTP 长轮询──>  Figma 插件  ──figma API──>  画布
                         localhost:8790
```

- 插件（Figma 里跑）有完整 `figma` API，但没网络服务器能力，只能主动来取活。
- 本地桥（一个 Node 进程）一边对 DSH 是 MCP server，一边对插件是 HTTP 端点。
- **画布内容只会经本地桥进入你自己配置的模型**，没有任何中转服务器。

模型能拿到 6 个工具，日常你只需要知道名字：

| 工具 | 干什么 | 碰不碰画布 |
|---|---|---|
| `status` | 看链路、当前文件/页面、你的选区 | 只读 |
| `ping` | 测往返延迟 | 只读 |
| `describe` | 把画布读成结构化 JSON（含 layout / fills / 变量绑定） | 只读 |
| `screenshot` | 导出节点成图片**喂给模型看** | 只读 |
| `apply` | 批量写：create / update / move / rename / delete | **会改** |
| `tokens` | 设计变量（tokens）：list / audit / bind / create / delete | **会改** |

## 2. 先确认它现在是好的（本次实测结果）

不想读表的话，结论是：**当前这套是可用的**，插件 → 桥 → 模型整条链路都跑通了。

### 2.1 静态检查（不需要 Figma 开着）

| 检查 | 命令 | 结果 |
|---|---|---|
| 插件产物是合规经典脚本 | `pnpm verify:plugin` | ✅ `dist/code.js` 110592 字节纯脚本，`ui.html` 存在 |
| 桥的协议层（60 项） | `pnpm smoke` | ✅ All smoke checks passed |
| 插件序列化器（45 项） | `pnpm test:serializer` | ✅ All serializer checks passed |
| 插件写执行器（125 项） | `pnpm test:apply` | ✅ All apply checks passed |
| 三个包类型检查 | `pnpm typecheck` | ✅ plugin / bridge / protocol 全部 exit 0 |

### 2.2 构建身份核对（最关键的一步）

「构建过了」和「Figma 里跑的就是刚构建的那份」是两件事，所以插件产物带一个 **build id**
（编译产物的 sha256 前 8 位）。本次核对：

```
磁盘产物 packages/plugin/dist/code.js 里的 id ........ 49408afc
用 src/code.ts 重新编译 + 打戳，与磁盘产物比对 ....... 逐字节完全相同
反推（去掉 id 后重新哈希前 8 位）.................... 49408afc ✅ 自洽
Figma 面板 / status 上报的 id ...................... 49408afc ✅ 一致
```

**为什么值得单列**：源码 → 产物 → Figma 里跑的那份，任何一环掉队都会让「我明明改了」变成
玄学。这三处 id 一致，就排除了这种情况。

### 2.3 活链路实测（需要桥和插件都在跑）

| 检查 | 结果 |
|---|---|
| `status` 往返 | 2 ms |
| `ping`（echo 回来 + 插件自己盖时间戳） | 1 ms |
| `describe` 读选中节点 | 3 ms |
| `screenshot` 导出真实像素 | ✅ 1728×936 PNG，24 KB，图像可视 |
| 当前文件 / 页面 | `Accfox` · `客户端V2.0` |

到这里「插件自称在线」已经被证伪过了：真的读到了画布节点，也真的拿到了图。

### 2.4 你自己复验的 30 秒版本

1. 打开 Figma → 运行 `Plugins → Development → DSH Figma Bridge`
   （`manifest.json` 现在带发布用的 `id: 1680977634792093219`；若你上次导入是在加 `id` 之前，
   需要**重新导入**一次才能算作同一个插件）
2. 面板右上角应显示 `v0.1.0 · p1 · 49408afc`，状态点绿色 `connected`
3. 终端里 `curl http://localhost:8790/figma/health`
   → 应看到 `"ok": true`，且**恰好一条** `"connected": true` 的实例
4. 回到 DSH 里说「看看我选中的这个框」→ 模型调用 `status`/`describe` 并答对文件与选区

## 3. 面板怎么读

面板是真话的唯一来源，逐行看：

| 位置 | 说明 |
|---|---|
| 左上状态点 + 文字 | `connected` 绿＝通了；`connecting` 蓝＝正在连；`offline` 红＝连不上本机程序；`error` 黄＝连上了但出问题（详情在下面一行） |
| 右上 `v0.1.0 · p1 · 49408afc` | 插件版本 · 协议版本 · **build id**。**只有 build id 每次构建都会变**，所以它是判断「Figma 里跑的是不是我刚写的那份」的唯一依据 |
| 第二行灰字 | 人话版状态。例如一行 `No app found at http://localhost:8790 — connection refused`，或 `Version mismatch… Update both to the same release`。**对用户可见的文案一律说人话**：什么坏了、下一步做什么 |
| `File` / `Page` / `Selected` | 本机程序认为你在看哪个文件、哪一页、选了什么——用来确认「我改的是这个文件吗」 |
| `Commands` | 本机程序**可以**请求本插件做什么。它不会自己跑；和对面期望的不一致时，说明两边版本不同步 |
| `Served` | 本次运行已执行多少条命令 |
| `Port` + `Apply` | 改端口（改完见 §7 的端口三处对齐） |
| 日志区 | 每条命令一行：`ok/fail 命令名 (耗时 ms)`；断线重连、协议不匹配也记在这。**这一区刻意保留原始技术串**——会看这里的人是开发者，那里事实本身就是要找的东西 |
| `Refresh` / `Stop plugin` | 手动刷新面板 / 结束插件 |

## 4. 日常怎么用

### 4.1 从零开始（每次打开 Figma 都要做）

1. 确认桥在跑：`curl http://localhost:8790/figma/health` 有响应。没有 → 重启 DSH Desktop（桥由 DSH 托管）
2. Figma 里运行 `Plugins → Development → DSH Figma Bridge`
3. 面板显示 `connected`，右上 build id 是你期望的那份
4. **选中**你想让模型看的节点（`describe` / `screenshot` 默认作用在选区上）
5. 在 DSH 里下指令

### 4.2 指令怎么写更省事

模型能自己读画布，但**先给它坐标**能省好几轮：

| 想干的事 | 这么说 |
|---|---|
| 摸清现状 | 「看看我选中的这块，用 describe 读一下结构」 |
| 统一间距 | 「把这一页所有卡片的间距统一成 8 的倍数，改完截图给我看」 |
| 一次搭一屏 | 「按这个描述搭一个登录页，一次 apply 建完整棵树，然后截图」 |
| 查硬编码色值 | 「对这个页面做 tokens audit，列出手写色值和可替换的变量」 |
| 判断改动对不对 | 「改完截图，告诉我哪里和设计不一致」 |

**「改完截图」这句话值得每次都带上。** `describe` 说的是文档*声称*的样子，
`screenshot` 展示的是你*实际看到*的样子——两者的落差就是设计 bug 的藏身处。

### 4.3 一次调用 = 一个 undo

`apply` 的批量操作在同一个 undo 步里。所以：

- 让模型**一次调用搭完整屏**，而不是四十次小改（否则你要按四十次 ⌘Z）
- 想整体回退就按一次 ⌘Z
- 如果某条 op 失败，模型的报错里会列出**已经建出来的节点**——那些节点确实在画布上了，别以为整批没生效

### 4.4 人和模型同时改稿

模型正在改的时候你手动拖图层，两边互不知情，会打架：

- 模型改之前会先读（`describe`），但读完之后你动过，它就基于旧认知写
- 建议：模型跑一批 `apply` 的时间里别手动编辑；等它截图回报后再动
- 这是「人机协作」而不是「交钥匙」模式，心里有数就行

## 5. 改了代码之后怎么让它生效

| 你改了什么 | 要做什么 | 别做什么 |
|---|---|---|
| `packages/plugin/src/*` | 重跑 `pnpm build:plugin`，然后在 Figma 里**关掉插件再运行一次**（开发插件每次运行都从磁盘重读 `main`/`ui`） | 不用重新 `Import plugin from manifest…` |
| `manifest.json`（权限 / `networkAccess` / `id` 等标识 / `main`·`ui` 路径） | 必须 `Import plugin from manifest…` **重新导入**（manifest 只在导入时读取） | 光重跑插件不生效 |
| 只改了桥（`packages/bridge/*`） | 结束桥进程即可，DSH 会在退避内自动重连并刷新工具集 | 不用重启 DSH |
| DSH profile 补丁（`cordis.patch.yml`） | **必须重启 DSH Desktop** | 该补丁只在应用启动时读，不热加载 |

> **重载后第一件事：对 build id。** 面板右上角 ≠ 你刚构建的 id，就说明 Figma 还在跑旧产物。

## 6. 出问题先看这三处

排查顺序固定，能省很多猜：

1. **面板右上 build id** —— 是不是你刚构建的那份？（不是 → 见 §5）
2. **面板状态点** —— `connected` / `offline` / `error`？
3. **`curl http://localhost:8790/figma/health`** —— 桥活着吗？有几个插件连着？

`health` 会同时列出**曾经连过但已掉线**的实例（`"connected": false`），那是历史记录不是故障。
判断「能不能用」只看有没有**恰好一条** `"connected": true`。

### 常见症状对照表

| 现象 | 原因 | 处理 |
|---|---|---|
| 面板 `offline`，`health` 也连不上 | 桥没跑 | 重启 DSH Desktop；或临时 `pnpm serve:standalone` |
| 面板 `offline`，但 `health` 正常 | 端口不一致，或 manifest 的 `allowedDomains` 没跟着改（被 CSP 拦，只在插件开发者控制台可见） | 对齐三处端口，见 §7 |
| 模型说插件报「Multiple plugins connected」类似错误 | 同一文件里开了**两个**插件实例，路由未实现 | 除了要用的那个，其余面板全部关掉 |
| 模型调用工具一直失败但面板是绿的 | 桥连上的是**另一个** Figma 文件/页面的实例 | `status` 看 `fileName`/`page` 是不是你要的那个 |
| 面板出现 `[object Object]` | 旧产物。Figma 沙箱的 `fetch` 抛的是普通对象而非 `Error` | 重建后重跑插件；用 build id 确认已换新 |
| 命令超时 | 大批量 `apply` 或大图导出超过预算 | 拆小批次；超时提示会说明「命令可能仍在 Figma 里执行」，去看一眼画布 |
| 模型看不到 `mcp__figma__*` 工具 | DSH profile 补丁没生效 | `--dump-config` 自检，日志搜 `patch: entry` |

## 7. 配置项

| 项 | 默认 | 说明 |
|---|---|---|
| `FIGMA_BRIDGE_PORT` | `8790` | 改端口要**同时**改插件面板端口和 `manifest.json` 的 `allowedDomains`，否则被 CSP 拦掉 |
| `FIGMA_BRIDGE_HOST` | `127.0.0.1` | 桥会自动附带绑定 `::1`，两族都只在本机。**不要改成 `0.0.0.0`** |
| `FIGMA_BRIDGE_TIMEOUT_MS` | `120000` | 单条命令预算 |
| `FIGMA_BRIDGE_LOG` | `info` | `debug` / `info` / `warn` / `error`，日志走 stderr |

> **端口为什么这么脆**：`allowedDomains` 只能枚举固定端口，而 Figma 的 manifest 校验器
> **只接受 `http://localhost:<端口>`，写 `127.0.0.1` 会被判为非法 URL**。所以桥必须同时监听两族回环。

## 8. 隐私与安全

- 网络面：桥只绑回环地址，插件只被允许访问 `http://localhost:8790`（manifest 里写死）
- 数据面：画布内容经本地桥进入**你自己配置的模型**；没有第三方中转服务器
- 风险面：本机任意进程都能访问 8790 端口来驱动你的 Figma。当前只靠 loopback 隔离，
  配对码机制在规划中（见 `plan.md` 风险表）
- 结论：**别把 `FIGMA_BRIDGE_HOST` 改成 `0.0.0.0`**，那等于把画布控制权交给整个局域网

---

## 9. 不想用了

1. 面板 `Stop plugin`，或 Figma 菜单关掉插件
2. 想彻底断开：删掉 DSH profile 补丁里的 `- id: mcp-figma` 条目，重启 DSH
3. 想卸插件：Figma 里 `Plugins → Development → 右键该插件 → Remove`

## 10. 一句话记住

**绿灯 + build id 对得上 + `health` 里恰好一条 connected = 可用。**
三样里缺一样，先修那一样，别猜模型为什么不动手。
